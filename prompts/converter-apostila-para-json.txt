9.3. LISTAS
----------------------------------------------------------------------

Utilize preferencialmente:

  "itens": [

  ],
  "tipo_lista": "nao_ordenada"

Não substitua explicações complexas por listas telegráficas.


----------------------------------------------------------------------
9.4. TABELAS
----------------------------------------------------------------------

Utilize preferencialmente:

{
  "titulo": "...",
  "colunas": [
    "Coluna 1",
    "Coluna 2"
  ],
  "linhas": [
    [
      "Conteúdo 1",
      "Conteúdo 2"
    ],
    [
      "Conteúdo 3",
      "Conteúdo 4"
    ]
  ],
  "nota": ""
}

Regras:

- mantenha correspondência entre colunas e linhas;
- prefira tabelas de 2 a 5 colunas;
- não coloque parágrafos gigantes nas células;
- divida tabelas excessivamente complexas;
- utilize títulos claros;
- utilize tabelas somente quando melhorarem a compreensão.


----------------------------------------------------------------------
9.5. FÓRMULAS E EQUAÇÕES
----------------------------------------------------------------------

Utilize preferencialmente:

{
  "titulo": "...",
  "latex": "...",
  "texto_linear": "...",
  "descricao": "...",
  "variaveis": [
    {
      "simbolo": "...",
      "descricao": "..."
    }
  ],
  "unidades": "..."
}

O campo "texto_linear" deverá oferecer representação acessível.

Explique as variáveis relevantes.

Escape corretamente barras invertidas dentro de strings JSON.


----------------------------------------------------------------------
9.6. CÓDIGO
----------------------------------------------------------------------

Utilize preferencialmente:

{
  "titulo": "...",
  "linguagem": "...",
  "codigo": "..."
}

Não envolva o código em Markdown.

======================================================================
15. QUESTÕES DE MÚLTIPLA ESCOLHA
======================================================================

Quando utilizar múltipla escolha:

- produza preferencialmente 4 ou 5 alternativas;
- utilize IDs como A, B, C, D e E;
- mantenha apenas uma alternativa correta, salvo lógica explicitamente
  diferente permitida pela questão;
- crie distratores plausíveis;
- evite alternativas absurdas;
- evite pistas gramaticais;
- evite diferença exagerada de tamanho;
- evite "todas as anteriores";
- evite "nenhuma das anteriores" como recurso preguiçoso.

A resposta no gabarito deverá corresponder EXATAMENTE ao ID da alternativa
correta.

Exemplo:

"resposta": "C"

Não escreva no campo de resposta:

"A alternativa C está correta."


======================================================================
16. GABARITOS COMENTADOS
======================================================================

Toda questão deverá possuir exatamente um gabarito correspondente.

Não poderá existir:

O comentário deve explicar a resposta.

Quando pertinente, forneça:

- fundamento;
- resolução;
- análise das alternativas;
- erro provável;
- seções que devem ser revisadas.

Não forneça apenas a letra correta.

Para múltipla escolha, analise alternativas quando isso tiver valor
pedagógico.

======================================================================
17.1. REGRA CRÍTICA PARA "topicos_relacionados"
======================================================================

ATENÇÃO:

O campo:

objetivos_aprendizagem[*].topicos_relacionados

NÃO recebe nomes de assuntos.

NÃO recebe palavras-chave.

NÃO recebe títulos livres.

NÃO recebe descrições textuais.

NÃO recebe valores de "topicos_cobertos".

O campo "topicos_relacionados" funciona, neste aplicativo, como uma
REFERÊNCIA ESTRUTURAL.

Cada valor de "topicos_relacionados" deverá ser EXATAMENTE um ID
existente em:

mapa_estrutura[*].id

Portanto:

CORRETO:

{
  "id": "raciocinio_logico_matematico_obj_001",

======================================================================
17.2. ONDE DEVEM FICAR OS NOMES DOS ASSUNTOS
======================================================================

Os nomes textuais dos assuntos pertencem principalmente ao campo:

mapa_estrutura[*].topicos_cobertos

Exemplo:

{
  "id": "raciocinio_logico_matematico_sec_01",
  "parent_id": "raciocinio_logico_matematico_parte_01",
  "ordem": 1,
  "nivel": 2,
  "tipo": "secao",
  "titulo": "Estruturas lógicas e proposições",
  "descricao": "Introdução às estruturas lógicas e às proposições.",
  "objetivos_ids": [
    "raciocinio_logico_matematico_obj_001"
  ],
  "topicos_cobertos": [
    "estruturas lógicas",
    "proposições"
  ],
  "tipos_de_conteudo_previstos": [
    "paragrafo",
    "conceito_chave",
    "exemplo_resolvido"
  ],
  "importancia": "fundamental",
  "status": "gerado"
}

Nesse caso, o objetivo correspondente deverá utilizar:

"topicos_relacionados": [
  "raciocinio_logico_matematico_sec_01"
]

e NÃO:

"topicos_relacionados": [
  "estruturas lógicas",
  "proposições"
]


======================================================================
17.3. RELAÇÃO BIDIRECIONAL ENTRE OBJETIVOS E SEÇÕES
======================================================================

Mantenha coerência entre:

mapa_estrutura[*].objetivos_ids

e:

objetivos_aprendizagem[*].topicos_relacionados

Se a seção:

"raciocinio_logico_matematico_sec_01"

possuir:

"objetivos_ids": [
  "raciocinio_logico_matematico_obj_001"
]

então o objetivo:

"raciocinio_logico_matematico_obj_001"

deverá possuir, quando essa for sua seção relacionada:

"topicos_relacionados": [
  "raciocinio_logico_matematico_sec_01"
]

Essa relação deverá ser semanticamente consistente.


======================================================================
17.4. OBJETIVO RELACIONADO A MAIS DE UMA SEÇÃO
======================================================================

Quando um mesmo objetivo for desenvolvido em mais de uma seção, liste
TODOS os IDs das seções correspondentes.

Exemplo:

{
  "id": "matematica_obj_010",
  "ordem": 10,
  "descricao": "Resolver situações-problema envolvendo razão, proporção e porcentagem.",
  "nivel_cognitivo": "resolver",
  "importancia": "central",
  "topicos_relacionados": [
    "matematica_sec_11",
    "matematica_sec_12",
    "matematica_sec_13"
  ]
}

Todos esses IDs deverão existir previamente em:

mapa_estrutura[*].id


======================================================================
17.5. OBJETIVOS E EXERCÍCIOS
======================================================================

Todo objetivo deverá ser efetivamente desenvolvido no conteúdo.

Objetivos centrais ou fundamentais deverão, sempre que pedagogicamente
adequado, ser avaliados por exercícios.

Quando um exercício avaliar determinado objetivo:

exercicios[*].objetivos_ids

deverá utilizar o ID do objetivo.

Exemplo:

"objetivos_ids": [
  "raciocinio_logico_matematico_obj_001"
]

Nunca utilize a descrição textual do objetivo nesse campo.


======================================================================
17.6. VALIDAÇÃO OBRIGATÓRIA DOS OBJETIVOS
======================================================================

Antes de finalizar o JSON, execute internamente esta validação para
CADA objetivo:

1. confirme que "id" é único;

2. confirme que "nivel_cognitivo" utiliza valor permitido pelo schema;

3. confirme que "importancia" utiliza valor permitido pelo schema;

4. leia cada valor de "topicos_relacionados";

5. procure esse valor EXATAMENTE em:

   mapa_estrutura[*].id

6. se não existir correspondência exata, o valor está INVÁLIDO;

7. substitua-o pelo ID correto da seção;

8. nunca transforme automaticamente nomes de tópicos em IDs sem
   verificar a estrutura;

9. confirme que a seção referenciada realmente desenvolve aquele
   objetivo;

10. confirme, quando aplicável, que o ID do objetivo também aparece em:

    mapa_estrutura[*].objetivos_ids

Não conclua o arquivo enquanto existir qualquer valor de
"topicos_relacionados" que não corresponda exatamente a um ID existente
em "mapa_estrutura".


======================================================================
17.7. REGRA DE NÃO AMBIGUIDADE
======================================================================

Apesar do nome "topicos_relacionados", interprete este campo, para este
aplicativo, como:

"IDs das unidades estruturais relacionadas ao objetivo"

e NÃO como:

"nomes dos tópicos relacionados".

Essa interpretação é OBRIGATÓRIA durante toda a geração.


======================================================================
18. ORGANIZAÇÃO E HIERARQUIA
======================================================================

Utilize "mapa_estrutura" para representar a organização pedagógica.

Organize, quando necessário:

parte
→ capítulo
→ seção
→ subseção
→ subsubseção.

Não utilize profundidade artificial.

Prefira estrutura clara.

Cada item filho deverá possuir parent_id válido.

Não crie ciclos.

A estrutura resumida do cabeçalho deverá permanecer consistente com
"mapa_estrutura".

Cada section_id usado em "conteudo" deverá corresponder a um item
existente no mapa.


======================================================================
19. IDENTIFICADORES
======================================================================

Todos os IDs deverão ser:

- únicos;
- estáveis;
- legíveis;
- sem espaços;
- sem acentos;
- sem caracteres problemáticos.

Crie "id_materia" a partir do nome da matéria em snake_case.

Exemplos:

Língua Portuguesa
→ lingua_portuguesa

Direito Administrativo
→ direito_administrativo

Raciocínio Lógico-Matemático
→ raciocinio_logico_matematico

Para evitar colisões, prefixe identificadores com id_materia sempre que
apropriado.

Exemplos:

lingua_portuguesa_cap_01
lingua_portuguesa_sec_01_01
lingua_portuguesa_obj_001
lingua_portuguesa_bloco_001
lingua_portuguesa_q_001
lingua_portuguesa_fonte_001
lingua_portuguesa_ref_001
lingua_portuguesa_asset_001

Não reutilize o mesmo ID indevidamente.

Toda referência interna deverá apontar para um ID existente.

Quando o assunto depender de informação verificável, atualizável,
normativa, científica ou institucional, realize pesquisa antes de gerar
o arquivo final.

Priorize:

1. legislação original;
2. documentos normativos originais;
3. fontes governamentais;
4. órgãos oficiais;
5. universidades;
6. instituições científicas;
7. artigos científicos;
8. livros reconhecidos;
9. manuais técnicos;
10. documentação oficial;
11. fontes secundárias confiáveis.

Não utilize blogs genéricos como fonte principal quando houver fonte
primária.

Não invente fontes.

======================================================================
22. SOURCE_REFS
======================================================================

Utilize source_refs quando um bloco, questão ou gabarito depender
diretamente de uma fonte registrada.

Todo source_id deverá existir em "fontes".

Utilize localizador específico quando disponível, por exemplo:

- art. 37;
- cap. 2;
- seção 4;
- p. 52;
- item 3.1.

Não associe fontes aleatoriamente apenas para aparentar fundamentação.


======================================================================
23. REFERÊNCIAS
======================================================================

A lista "referencias" deverá conter apenas fontes efetivamente utilizadas
e apropriadas para apresentação bibliográfica.

Não invente dados bibliográficos.

Quando determinado dado não estiver confirmado e o schema permitir
null, utilize null.

Não complete artificialmente:

- edição;
- local;
- editora;
- ano;
- DOI;
- URL.

É melhor uma referência verdadeira com campos nulos permitidos do que
uma referência ficticiamente completa.

27. ACESSIBILIDADE
======================================================================

Não dependa exclusivamente de:

Tabelas devem possuir títulos e cabeçalhos compreensíveis.


======================================================================
28. CONTROLE DE REPETIÇÕES
======================================================================

Monitore repetição semântica durante toda a geração.

Quando um conceito já estiver completamente explicado:

- não repita a explicação integral;
- faça breve retomada;
- acrescente apenas o novo aspecto.

Evite:

- definição repetida;
- exemplo repetido com nomes diferentes;
- mesma observação em vários capítulos;
- alertas duplicados;
- revisões idênticas;
- exercícios praticamente iguais.

Realize auditoria antirrepetição antes da entrega.


======================================================================
29. DISTRIBUIÇÃO EQUILIBRADA
======================================================================

Não concentre todo o aprofundamento nos primeiros assuntos.

Todos os ASSUNTOS informados deverão receber profundidade proporcional
à sua relevância e complexidade.

Evite o padrão:

primeiros capítulos muito detalhados
+
últimos capítulos excessivamente resumidos.

Planeje toda a matéria antes da serialização final.


======================================================================
30. QUALIDADE PEDAGÓGICA
======================================================================

Antes de considerar cada grande seção concluída, verifique internamente:

- o estudante sabe o que aprenderá?
- o conteúdo foi realmente explicado?
- os fundamentos estão presentes?
- os conceitos foram contextualizados?
- há exemplos suficientes?
- conceitos semelhantes foram diferenciados?
- exceções foram explicadas?
- erros frequentes foram abordados?
- a sequência é lógica?
- os exercícios avaliam o conteúdo ensinado?
- o gabarito explica a solução?
- existe síntese quando apropriado?

Se houver deficiência relevante, corrija antes de prosseguir.

======================================================================

Preencha o cabeçalho conforme o JSON Schema.

- letras minúsculas;
- remova acentos;
- remova caracteres especiais.

se não houver código fornecido e o schema permitir null:

null

Não invente código.

Para "materia":

utilize o nome real da MATÉRIA.

Para "titulo_sugerido":

======================================================================
35. INTEGRIDADE REFERENCIAL
======================================================================

Antes da entrega, valide internamente:

MAPA:

- todo parent_id existe ou é null quando permitido;
- não existem ciclos.

CONTEÚDO:

- todo section_id existe no mapa;
- não existem seções duplicadas indevidamente.

OBJETIVOS:

- todo objetivo referenciado existe.
- todo objetivo possui ID único;
- todo ID presente em mapa_estrutura[*].objetivos_ids existe em
  objetivos_aprendizagem[*].id;
- TODO valor de
  objetivos_aprendizagem[*].topicos_relacionados
  deve corresponder EXATAMENTE a um valor existente em
  mapa_estrutura[*].id;
- nomes de assuntos, palavras-chave e valores de "topicos_cobertos"
  são PROIBIDOS em "topicos_relacionados";
- quando um objetivo estiver ligado a várias seções, todos os valores
  devem ser IDs válidos dessas seções.

FONTES:

- todo source_id referenciado existe.

ASSETS:

- todo asset_ref existe.

QUESTÕES:

- todos os section_refs existem;
- todos os objetivos referenciados existem.

GABARITOS:

- todo question_id aponta para uma questão existente;
- cada questão possui exatamente um gabarito.

REVISÃO:

- todo revisar_section_refs aponta para seção existente.

MÚLTIPLA ESCOLHA:

- resposta corresponde exatamente ao ID de uma alternativa existente.

======================================================================
43. AUDITORIA FINAL OBRIGATÓRIA
======================================================================

Antes de gerar o arquivo final, execute internamente:

ETAPA 1 — ESCOPO

Confirme que TODOS os ASSUNTOS foram abordados.

ETAPA 2 — DIDÁTICA

Confirme que os assuntos foram ensinados, e não apenas citados.

ETAPA 3 — PROFUNDIDADE

Confirme que não existem capítulos artificialmente superficiais.

ETAPA 4 — MAPA

Verifique hierarquia, níveis e parent_id.

ETAPA 5 — OBJETIVOS E REFERÊNCIAS ESTRUTURAIS

Para cada item de "objetivos_aprendizagem":

1. valide o ID do objetivo;

2. valide o nível cognitivo;

3. valide a importância;

4. percorra TODOS os valores de "topicos_relacionados";

5. confirme individualmente que cada valor existe EXATAMENTE em:

   mapa_estrutura[*].id

6. rejeite valores como:

   "proposições"
   "negação"
   "porcentagem"
   "sintaxe"
   "interpretação de textos"

   quando forem apenas nomes de assuntos;

7. substitua-os pelos IDs estruturais correspondentes, como:

   "raciocinio_logico_matematico_sec_01"
   "lingua_portuguesa_sec_03"
   "matematica_sec_12"

8. confirme a relação inversa com:

   mapa_estrutura[*].objetivos_ids

9. não finalize enquanto houver referência inválida.

ETAPA 6 — CONTEÚDO

Verifique section_id e ordem.

ETAPA 7 — BLOCOS

Verifique se todos os tipos são permitidos.

ETAPA 8 — FORMATO INTERNO

Verifique especialmente:

- texto → "texto";
- lista → "itens";
- tabela → "colunas" e "linhas";
- fórmula/equação → "latex" e "texto_linear";
- código → "linguagem" e "codigo";
- caixas → "titulo" e/ou "texto";
- visual → asset real.

ETAPA 9 — FONTES

Confirme que nenhuma fonte foi inventada.

ETAPA 10 — EXERCÍCIOS

Confirme que avaliam conteúdo ensinado.

ETAPA 11 — GABARITOS

Confirme correspondência 1:1.

ETAPA 12 — RESPOSTAS
